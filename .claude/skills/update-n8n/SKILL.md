# Update n8n to Latest Stable Version

This skill automates the process of updating the n8n Docker image to the latest stable version in this repository.

## How the n8n version is defined

The n8n version is pinned in `Dockerfile.n8n` on the `FROM` line:
```
FROM n8nio/n8n:<version>
```

The deploy pipeline in `.github/workflows/n8n-deploy.yml` works as follows:
1. Builds the `Dockerfile.n8n` image (which contains the n8n version) for `linux/arm64`
2. Pushes the image to GHCR with a tag generated by `docker/metadata-action`
3. **Generates a `docker-compose.prod.yaml` inline** within the workflow — this compose file references the just-built image via `$IMAGE_WITH_TAG` (from `steps.meta-n8n.outputs.tags`), so it always points to the image built in that same run
4. Syncs the compose + env to the VPS and runs `docker compose up -d`

The compose file in the workflow does NOT hardcode the n8n version — it dynamically uses the image built from `Dockerfile.n8n`. Therefore, **changing the version tag in `Dockerfile.n8n` is the only change needed** to update n8n in production. No workflow modifications are required.

## Step-by-step process

### 1. Get the current version

Read `Dockerfile.n8n` and extract the version from the `FROM n8nio/n8n:<version>` line.

### 2. Find the latest stable version

Use the Docker Hub API to get the latest stable n8n tags:

```bash
curl -s "https://hub.docker.com/v2/repositories/n8nio/n8n/tags/?page_size=50&ordering=last_updated" | python3 -c "
import sys, json
data = json.load(sys.stdin)
tags = [t['name'] for t in data['results'] if t['name'][0].isdigit() and 'beta' not in t['name'] and 'next' not in t['name'] and 'rc' not in t['name'] and 'alpha' not in t['name']]
if tags:
    print(tags[0])
else:
    print('NOT_FOUND')
"
```

If the latest version equals the current version, inform the user that n8n is already up to date and stop.

### 3. Fetch release notes summary

Use WebFetch to access `https://docs.n8n.io/release-notes/` and extract a summary of changes for the target version (or the most recent releases if the specific version isn't detailed). Keep the summary concise — focus on breaking changes, new features, and important fixes.

### 4. Update the Dockerfile

Edit `Dockerfile.n8n` and replace the version tag in the `FROM` line. Only change the version number, nothing else.

### 5. Create branch, commit, and open PR

```bash
# Create a new branch
git checkout -b chore/update-n8n-to-<new-version>

# Stage and commit
git add Dockerfile.n8n
git commit -m "chore: update n8n to <new-version>"

# Push and create PR
git push -u origin chore/update-n8n-to-<new-version>
```

Create the PR using `gh pr create` with this structure:

```
Title: chore: update n8n to <new-version>

Body:
## Summary
- Update n8n from `<old-version>` to `<new-version>`

## Release Notes Summary
<summary from step 3>

## Deployment
This PR will trigger the deploy workflow on merge to `main`, which:
1. Builds the Docker image for `linux/arm64`
2. Pushes to GHCR
3. Deploys to VPS via SSH with `docker compose up -d`

## Test plan
- [ ] Review release notes for breaking changes
- [ ] Merge and monitor deploy workflow
- [ ] Verify n8n is running correctly at https://n8n.ivanildobarauna.dev
```

### 6. Present the result

Return to the user:
- The PR URL
- Current version -> new version
- Release notes summary
- Any breaking changes flagged
